# 01 — Product

---

## 목표

> **팀 업무 시각화 — "지금 누가 뭐 해?"라는 질문이 사라지게 만든다.**

팀원이 서로 업무 현황을 묻고 답하는 데 쓰는 시간을 없앤다.
보드를 열면 누가 무엇을 하고 있고, 언제까지인지 한눈에 보인다.

---

## 페르소나

| 항목 | 내용 |
|---|---|
| **대상** | 10명 규모 스타트업의 팀 리더 |
| **연령대** | 30~40대 |
| **상황** | 슬랙·이메일로 진행 상황을 수시로 확인해야 하는 피로감 |
| **핵심 니즈** | 물어보지 않아도 팀 전체 업무 현황이 보이는 단일 화면 |

## MVP 범위

### 기능

| 기능 | 설명 |
|---|---|
| 태스크 추가 | 제목·설명·상태·마감시각 입력 후 생성 |
| 태스크 목록 | 전체 태스크를 상태별로 구분하여 표시 |
| 태스크 수정 | 제목·설명·상태·마감시각 변경 |
| 태스크 삭제 | 태스크 영구 삭제 |

CRUD 4종 모두 별도 페이지 이동 없이 **한 화면**에서 완결된다.

### 상태 분류

```
todo  →  in_progress  →  done
```

### 마감시각 (due_at)

- 날짜만이 아닌 **날짜 + 시간** 까지 지정한다.
- 형식 예시: `2026-05-12 18:00`
- UI 입력: `datetime-local` 인풋 사용

### 테마

- 라이트 / 다크 토글
- 선택값은 `localStorage`에 저장 — 새로고침 후에도 유지

### 반응형

- 최소 지원 너비: **360px**
- 레이아웃이 360px에서 깨지지 않아야 한다

## UI 톤 & 스타일

Mac OS 스타일을 기준으로 한다.

| 요소 | 방향 |
|---|---|
| 모서리 | 둥근 모서리 (`border-radius` 적극 사용) |
| 그림자 | 부드럽고 낮은 그림자 (`box-shadow` 다층 활용) |
| 카드 | 반투명 배경 (`backdrop-filter`, `rgba`) |
| 폰트 | 시스템 폰트 스택 (`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`) |
| 색상 | 화이트/그레이 계열 라이트, 딥그레이/차콜 계열 다크 |

## 확장 계획 (MVP 이후)

MVP 완성 후 다음 순서로 확장한다. 현재 범위에 영향을 주지 않도록 설계 단계에서 확장 지점을 열어둔다.

1. JWT 로그인 / 회원가입
2. 팀 단위 업무 분리
3. Kanban 보드 드래그&드롭
4. 팀 내 채팅
5. CI/CD 파이프라인 자동화

---

## MVP 범위 외 (명시적 제외)

아래 기능은 MVP에 포함하지 않는다. 요청이 들어와도 확장 단계 전까지 구현하지 않는다.

| 제외 항목 | 이유 |
|---|---|
| 외부 결제 | MVP 수익 모델 없음 |
| 네이티브 앱 (iOS/Android) | 웹 MVP 우선 |
| WebRTC (영상·음성) | 채팅도 확장 단계 |
| 외부 캘린더 연동 | 복잡도 대비 MVP 가치 낮음 |
| 파일 업로드 | 저장소·보안 설계 필요 |
| WebSocket 실시간 | MVP는 **폴링**으로 대체, WebSocket은 확장 단계에서 도입 |

## 성공 기준

MVP가 다음 조건을 모두 만족하면 완성으로 간주한다.

| 기준 | 검증 방법 |
|---|---|
| 새로고침 후 테마·데이터 유지 | 브라우저 새로고침 후 상태 확인 |
| 360px에서 레이아웃 미파괴 | Chrome DevTools 360px 뷰포트 확인 |
| API CRUD 4종 응답시간 200ms 이하 | 네트워크 탭 또는 테스트 측정값 |
| CRUD 4종 화면 동작 | 추가·목록·수정·삭제 E2E 흐름 확인 |
| 테마 토글 작동 | 토글 후 새로고침 시 테마 유지 확인 |
